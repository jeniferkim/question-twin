# 저장형 임베딩 검색 재현성과 성능 검증

## 목적

같은 입력에서 일관된 결과를 얻고, 반복 검색에 필요한 모델 초기화를 줄인다.
이 기능은 저장형 인덱스에 한정되며 기존 앱과 평가 파이프라인은 변경하지 않는다.

## 기능

- 기존 MiniLM 모델 및 고정 revision 유지
- 프로세스 내 모델 캐싱: 기본 오프라인 모델과 명시적 다운로드 허용 모델을 분리
- 공백 제거 후 최대 500자까지 검색 허용, 초과 시 `query_too_long` 오류 코드
- 빈 검색어는 기존과 같이 빈 결과 반환
- 기존 검색 결과의 다섯 필드 계약 유지
- 저장된 인덱스 및 비공개 원본 데이터의 변경 금지

## 실행 및 재현

프로젝트 가상환경을 활성화했거나 프로젝트 Python 경로로 명령을 실행한다.

```powershell
python -m unittest discover -s tests -p test_embedding_store.py -v
python -m unittest discover -s tests -v
python -m src.embedding.store verify --csv data/raw/question_twin/questions.csv
```

첫 두 명령은 합성 데이터 기반 단위 테스트이며, 마지막 명령은 이미 검수된
로컬 질문 CSV와 기존 임베딩 파일이 있는 환경에서만 사용할 수 있다.
원본 질문, 벡터, 로컬 파일 경로 등 비공개 내용을 공개 로그에 남기지 않는다.

## 검증 항목

1. 동일 정제 입력 두 번 처리 시 결과 일치
2. 동일 질문의 벡터·검색 Top 5 결과 재현
3. 기존 CSV 및 NPZ 덮어쓰기 차단
4. 검색 입력 500자 허용, 501자 거부
5. 검색 결과 필드 및 순서 유지
6. 모델 초기화 호출의 재사용 여부 확인
7. 모델 로딩 시간과 캐시 이후 검색 시간을 분리해 측정

## 2026-11-12 로컬 검증 결과

아래 수치는 승인된 로컬 질문 51건과 고정된 MiniLM 모델을 사용한
Windows PowerShell / Python 3.13.4 / CPU 환경의 단일 실행 결과다.
원본 질문·개별 식별자·벡터는 포함하지 않는다.

| 확인 항목 | 측정 및 검증 결과 |
| --- | --- |
| 데이터 정제 재실행 | 2회 동일 결과, 후보 171건·정제 질문 51건 |
| 임베딩 재계산 | 51 × 384차원, 재실행 및 기존 저장 벡터와 최대 절댓값 차이 0.00000000 |
| 정제 질문 길이 경계 | 5자 거부, 6자·500자 허용, 501자 거부 |
| 기존 출력 덮어쓰기 방지 | CSV 및 임베딩 NPZ 모두 통과 |
| 동일 질문 검색 재현성 | 3건 반복 결과 일치 및 각 원문 Top 1 확인 |
| 저장형 검색 길이 경계 | 500자 허용, 501자 `query_too_long` 거부 |
| 전체 단위 테스트 | 75개 통과(신규 회귀 테스트 포함) |
| 저장형 검색 호출 | 6회, 실제 모델 생성 1회, 캐시 미스 1회·적중 5회 |
| 첫 검색(모델 로딩 포함) | 13.22초 |
| 이후 캐시 검색 중앙값 | 18.90ms(동일 입력 5회) |
| 비공개 입력·출력 파일 | 검사 전후 변경 없음 |

최초 검색 시간은 모델 초기 로딩을 포함하고, 이후 검색 시간은
모델이 이미 로드된 상태의 측정값이다. 두 수치를 동일 조건의
성능 비교나 일반적인 서비스 속도 향상 배수로 해석하지 않는다.
또한 동일 문장 Top 1 재검색은 실제 중복 질문 탐지 정확도의 근거가 아니다.

## 한계

- 캐시는 Python 프로세스 단위이며, 앱을 다시 시작하면 모델을 다시 로드한다.
- 동시에 여러 요청이 시작되면 초기 로딩을 중복 수행할 가능성이 있다.
- 검색 입력 길이 제한은 저장형 인덱스 API에 적용된다. 기존 UI와 별개다.
- 동일 질문 Top 1 성공은 중복 질문 탐지 정확도를 입증하지 않는다.
- 작은 샘플에서의 검색 지연 시간은 일반 운영 성능을 보증하지 않는다.
- 실제 데이터 이용 허가와 개인정보 검토는 기술 검사와 별개다.
