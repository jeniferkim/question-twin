# 중복 판정 기준

`data/sample_questions.csv`의 `duplicate_group`, `category_code`, `split`을 정하고 검수할 때 따르는 기준입니다.

## 1. 중복의 정의

**같은 답변 하나로 해결되는 질문이면 같은 `duplicate_group`입니다.**

- 단어, 어순, 존댓말, 줄임말, 오타가 달라도 요청이 같으면 중복입니다.
- 상담 코드가 같아도 필요한 답변이 다르면 다른 묶음입니다.
- 한 문장에 요청이 두 개면 주된 요청을 기준으로 정합니다.
- 애매하면 다른 묶음으로 둡니다. (중복으로 잘못 묶는 쪽이 더 위험합니다.)

## 2. 예시

| 질문 A | 질문 B | 판정 | 이유 |
| --- | --- | --- | --- |
| 요금제 바꾸고 싶어요 | 지금 쓰는 요금제를 더 싼 걸로 바꾸려면 어떻게 해요? | 중복 | 표현은 달라도 같은 답 (요금제 변경 안내) |
| 휴대폰을 잃어버렸어요 | 폰 분실 신고하고 정지해 주세요 | 중복 | 분실 신고·정지 안내 하나로 해결 |
| 요금제 바꾸고 싶어요 | 요금 납부일을 바꾸고 싶어요 | 중복 아님 | "바꾸고 싶어요"는 같지만 요금제 변경과 납부일 변경은 안내가 다름 |
| 요금 납부일을 바꾸고 싶어요 | 자동이체 계좌를 다른 은행으로 바꾸고 싶어요 | 중복 아님 | 같은 상담 코드(PAYMENT_METHOD)지만 처리가 다름 |
| 휴대폰 소액결제를 막고 싶어요 | 휴대폰 소액결제 한도를 올리고 싶어요 | 중복 아님 | 같은 상담 코드(MICRO_PAYMENT)지만 차단과 한도 변경은 다름 |

## 3. 상담 코드

- 상담 코드 목록과 정의는 `data/consult_codes.csv`를 따릅니다.
- `aihub_category`는 AI Hub LG U+ 업무 유형 표기를 그대로 씁니다 (띄어쓰기 포함).
- 같은 묶음의 질문은 모두 같은 `category_code`를 가집니다.

## 4. tune / test 분리

- 기준값(threshold)을 정할 때는 `tune`, 마지막 성능 확인은 `test`를 씁니다 (약 7:3).
- **묶음 단위로** 나누므로 한 묶음이 양쪽에 걸치지 않습니다.
- 현재 샘플: tune 21개(10묶음) / test 9개(4묶음)
- `test`로 평가한 뒤에는 기준값을 바꾸지 않습니다.

## 5. 실데이터

- AI Hub 실데이터에는 같은 의미 질문 정답(`duplicate_group`)이 없으므로 이 기준으로 라벨링하지 않습니다.
- 실데이터는 "검색 결과 5개 중 같은 업무 유형 비율"로만 평가합니다 (#13).
- 실데이터와 그 문장·식별자·임베딩은 Git에 올리지 않습니다.

## 6. 검수 방법

```bash
python -m eval.check_data
```

아래 항목을 자동으로 확인합니다.

- 빈 질문, id 중복, 숫자가 아닌 id, 완전히 같은 질문
- 한 묶음에 상담 코드가 여러 개인 경우
- 한 묶음이 tune과 test에 나뉜 경우, `tune`/`test`가 아닌 split 값
- `consult_codes.csv`에 없는 상담 코드, 샘플에 한 번도 안 나온 상담 코드
- 질문이 1개뿐인 묶음
